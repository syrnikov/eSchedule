## What we're building

A single-page web app that answers one question at a glance: **"What should I be doing right now, and what's next?"**

I study online at Odesa State Agrarian University (OSAU) while working. The official schedule is a clunky table, every professor has a different Zoom/Meet link, and classes pause whenever there's an air alarm in Odesa oblast. This app pulls all of that into one calm screen: current time and day, the current or next class as the hero element with a big "Приєднатися" button, a status (live / starting soon / break / paused for air alarm / done for today), and the rest of today's classes below.

**Owner:** me, one user. Group `208-бак-3к денне 26-27`, **subgroup 1б**. UI language: **Ukrainian only**.

## Architecture (no servers to manage)

```
GitHub Actions (cron) ──scrapes──> OSAU schedule ──> data/schedule.json (committed to repo)
                                                            │
GitHub Pages (static site) <────────────────────────────────┘
        │
        ├── polls every 60s ──> Cloudflare Worker ──> https://ubilling.net.ua/aerialalerts/
        │                       (adds CORS header, caches 60s)
        │
        └── Zoom links ──> stored in browser localStorage (never committed)
```

**Why each piece exists:**

- **GitHub Pages** hosts the static site. Plain HTML/CSS/JS with ES modules, **no build step, no framework**. Keep it simple enough that I can read every file.
- **GitHub Actions** scrapes the schedule because the university site can't be fetched from a browser (CORS) and the schedule changes rarely. Runs a Node script, writes `data/schedule.json`, commits only if it changed.
- **Cloudflare Worker** proxies the air alarm feed. `ubilling.net.ua/aerialalerts/` is free and needs no token, but it sends **no CORS headers** (verified), so the browser can't call it directly. GitHub Actions cron is too slow and unreliable for alarms, so we use a tiny Worker instead.
- **localStorage for links**, because many Zoom links contain passcodes and the repo will likely be public (GitHub Pages on a private repo needs a paid plan). A settings screen lets me enter links and export/import them as JSON for backup.

## Data contracts

```json
  "subgroup": "1б",
  "source": "https://osau.edu.ua/pro-universytet/pratsivnykam/rozklad-zanyat/",
  "fetchedAt": "2026-09-28T06:00:00Z",
  "rangeFrom": "2026-09-28",
  "rangeTo": "2026-10-11",
  "classes": [
    {
      "date": "2026-09-28",
      "start": "08:15",
      "end": "09:35",
      "discipline": "Іноземна мова",
      "type": "Практичні",
      "room": "онлайн",
      "teacher": "Насакіна С. В.",
      "audience": "group"
    }
  ]

```

- `audience` is `"group"` or `"subgroup"`. Times are **Europe/Kyiv local time**.
- `room` and `teacher` may be empty strings (e.g. «Кураторська година», «Зустріч зі стейкхолдерами»).

### Links (localStorage key `pary.links.v1`)

```json
{ "Трактори і автомобілі|Практичні": "https://zoom.us/j/...", "Трактори і автомобілі|Лекції": "https://..." }
```

Key = `discipline|type`. Match by subject + class type, not by teacher alone, because the same subject has different teachers for lectures, practicals and labs. If no exact key exists, fall back to a teacher-only key `@Дядюра К. О.` if I've set one.

### Phase 1 — Scraper and parser

1. `parse.mjs`: turn `GetScheduleDataX` JSON rows (see `RECON.md`) into class objects. Watch out for:
   - `full_date` is `DD.MM.YYYY` → convert to ISO `2026-09-28`. Times come from `study_time_begin` / `study_time_end`.
   - **Subgroup filtering:** keep rows where `contingent` starts with `Група:`, keep `Підгрупа: 1б`, drop every other subgroup. Normalize before comparing (trim, collapse whitespace, and treat Latin/Cyrillic look-alike letters carefully).
   - `cabinet` / `employee_short` can be `null` → store as `""`.
   - Trim all text; some discipline names are truncated with a trailing `_` (e.g. «Соціальна робота в громаді_») — strip the trailing underscore. Otherwise keep names exactly as the source spells them (link keys depend on them).
2. `scrape.mjs`: request (with a descriptive User-Agent and `Content-Type: application/json`) the range **today → today + 13 days** (Europe/Kyiv), parse, write `data/schedule.json`. If the fetch or parse fails, or returns zero classes when the previous file had classes for that range, **exit non-zero and do not overwrite** the last good file.
3. Tests using the fixture, plus the expected data below.

### Phase 3 — Static UI with the real schedule

Build the main screen using `data/schedule.json`, with alarm state faked as `"clear"` for now.

**Layout (mobile-first, also good on desktop):**

1. Header: current time (large, `HH:MM`, updates every second without layout shift — use tabular numbers) and the date as «понеділок, 28 вересня».
2. **Hero card** — the current or next class: status label, discipline, type, teacher, time range, a progress bar or countdown, and a black pill **«Приєднатися»** button (opens the link in a new tab). If there's no link: show «Посилання немає» with a link to settings instead of the button.
3. «Сьогодні» list: remaining classes today as compact rows; finished ones dimmed.
4. «Завтра» preview: first class time + count.
5. Footer: «Розклад оновлено 28 вересня о 09:00» from `fetchedAt`. If older than 24h, show a warning.

**Visual style** — Дія's structure with monobank's warmth, iOS-like feel:

- Soft pastel gradient background (light blue → mint), white cards with large corner radius (~20–24px), subtle shadow, generous spacing, one idea per card.
- Font: **e-Ukraine** (the open Diia typeface, free to use). I'll download the woff2 files from the Ministry of Digital Transformation's site (thedigital.gov.ua/fonts) into `/fonts`. Fall back to `system-ui, -apple-system, "Segoe UI", sans-serif`.
- Black pill primary button, white text. High contrast everywhere.
- **Icons: Material Symbols Rounded, filled** (free, Apache 2.0; the closest free match to SF Symbols).
  - Load the variable font from Google Fonts with the axes set to `FILL 1`, and **subset it with the `icon_names` parameter** (names must be in alphabetical order) so we don't download thousands of unused icons. Keep the list of used icons in one place in `index.html` and update it whenever you add an icon.
  - Set `font-variation-settings: 'FILL' 1, 'wght' 500, 'GRAD' 0, 'opsz' 24` in one `.icon` class. Use `opsz` matching the rendered size (20 for inline, 24 default, 40–48 for the hero status).
  - Add a CSS fallback so a missing font never shows raw ligature text: hide `.icon` until `document.fonts` reports it loaded, and reserve its width to avoid layout shift.
  - Icons are decorative next to text: `aria-hidden="true"`. Icon-only buttons (e.g. settings) need an `aria-label` in Ukrainian.
  - Suggested mapping (adjust if something looks off): live `radio_button_checked`, soon `schedule`, paused/alarm `warning`, resumed `check_circle`, break `coffee`, done `celebration`, weekend `weekend`, nodata `cloud_off`, join button `videocam`, no link `link_off`, settings `settings`, lecture `school`, practical `edit_note`, lab `science`, stale data `history`.
- Accent colors used only for meaning: green for live, amber for starting soon, **red for air alarm**.
- Dark mode via `prefers-color-scheme` (monobank-style dark cards). Define all colors as CSS variables.
- Respect `prefers-reduced-motion`. Keep animations subtle.

### Phase 4 — Status engine (the core logic)

`computeStatus(now, classes, alarm)` must be a **pure function** with thorough unit tests. All time math in **Europe/Kyiv** using `Intl.DateTimeFormat` with `timeZone: "Europe/Kyiv"` — never trust the device's timezone.

| State | When | Label (UI) | Subtext example |
|---|---|---|---|
| `live` | now within a class, no alarm | Наживо | Ще 34 хв · Дядюра К. О. |
| `soon` | next class starts within 15 min | Почнеться за 15 хв | Трактори і автомобілі · практичне |
| `paused` | alarm active and a class is live or starting within 15 min | Пауза · повітряна тривога | Одеська область. Бережи себе 🙏 |
| `resumed` | alarm ended less than 10 min ago during a class | Відбій тривоги | Пара продовжується |
| `break` | between classes today | Перерва | Далі о 11:15 |
| `done` | no more classes today | На сьогодні все 🎉 | Завтра перша пара о 09:45 |
| `weekend` | Sat/Sun with no classes | Вихідні | Наступна пара в понеділок |
| `nodata` | schedule missing/stale for today | Немає розкладу | Спробуй оновити пізніше |

Rules:

- During an alarm, the class's scheduled end time does **not** change; we just show it as paused.
- If the alarm state is `"unknown"` (feed unreachable), **never show "no alarm"**. Show the normal status plus a small grey note «Статус тривоги невідомий».
- The alarm state gets **zero jokes**. Warm tone everywhere else, serious when it matters.

### Phase 5 — Air alarm via Cloudflare Worker

1. `worker/worker.js`: fetch `https://ubilling.net.ua/aerialalerts/`, return it with `Access-Control-Allow-Origin` set to my GitHub Pages origin only (not `*`), and cache the response for 60 seconds with the Cache API so we respect the feed's rate limits. Set a descriptive `User-Agent`. Return a clear JSON error on failure.
2. Response format: `{ "source": "...", "cachedat": "...", "states": { "Одеська область": { "alertnow": true, "changed": "..." }, ... } }`. Keys are Cyrillic (JSON-escaped). Look up `"Одеська область"`; put the region name in a config constant.
3. Known limitations: the feed is **oblast-level only**, and its `changed` timestamp is unreliable. So track "seen since" client-side from when we first observed `alertnow: true`.
4. `alarm.js`: poll every 60s, and immediately when the tab becomes visible again. Back off to 5 min after repeated failures.
5. Walk me through deploying with `wrangler` step by step, since I've never used Cloudflare Workers. Put the Worker URL in one config constant.
